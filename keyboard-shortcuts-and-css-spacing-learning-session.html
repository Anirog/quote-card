Keyboard shortcuts and CSS spacing

How I added keyboard shortcuts to the quote card, kept the instructions at the bottom of the screen, and removed a middle dot without closing the gap between the two instructions.

1. Session overview

I wanted to add two keyboard shortcuts to quote-card.html: n for a new quote and c for copying the current quote. I also wanted a small instruction at the bottom of the screen that would remain visible at every screen size.

After reviewing the page in the browser, I asked for the middle dot between the instructions to be removed. A CSS margin before the c key kept the two instructions the same apparent distance apart.

Demonstrated

The current HTML connects n to showRandomQuote() and c to copyCurrentQuote(). CSS fixes the instruction 16 pixels from the bottom of the browser window. The HTML no longer contains the middle dot.

Not demonstrated

We did not measure the old and new gaps in the browser's computed layout. We also did not test the finished page on several devices, browsers or keyboard layouts.

2. Problems encountered

Using the same code for buttons and keys

The page already had functions for showing and copying quotes. Writing separate versions for the keyboard would have duplicated those functions. A later change could then work for a button but not its keyboard shortcut.

Keeping the instructions visible without drawing attention

The instruction needed to stay at the bottom on narrow and wide screens without becoming part of the quote card. The page also needed enough bottom padding to stop the fixed instruction from covering the card.

Removing the dot without narrowing the gap

The original HTML placed a middle dot between the instructions and gave it an 8-pixel margin on each side. Deleting that element also deleted the width of the dot and both margins. Without replacement spacing, "Copy quote" would have moved closer to "New quote".

Verifying the served page

The normal server check could not start on port 3000 because another process was already using it. I started a temporary static server on port 8765 instead. A proxy first returned a 403 response, but bypassing the proxy for the local address returned the updated page successfully.

3. What was tried and learned

Reuse the existing functions

One keydown listener checks event.key and calls the same functions as the button click handlers:

if (event.key.toLowerCase() === 'n') {
  showRandomQuote();
} else if (event.key.toLowerCase() === 'c') {
  copyCurrentQuote();
}

The button and its keyboard shortcut therefore use the same quote selection, fade effect, clipboard text and copied confirmation.

Ignore keystrokes that should not trigger the feature

The listener stops when the user is typing in an editable field, holding a key down, or pressing Command, Control or Alt. The current page has no text field, but this check means a text field added later would not turn normal typing into quote commands.

Pin the instruction to the bottom of the window

position: fixed with bottom: 16px places the instruction 16 pixels from the bottom of the browser window. The body's 64-pixel bottom padding leaves room for it below the card.

Replace the dot with a CSS margin

I deleted the middle-dot element and added margin-left: 23px to the c key. That margin replaces the approximate width previously taken by the dot, its margins and the surrounding inline whitespace.

Evidence limit: the finished CSS uses 23 pixels because that was chosen to preserve the apparent gap. We did not measure both versions in the browser, so the session does not prove that their computed widths are identical.

4. Connected concepts

Keyboard events and existing button actions

A keyboard shortcut runs the same action as its button. Because both call the existing function, clicking and pressing a key use the same fade effect, random quote selection, clipboard text and "Copied" message.

Visible instructions and accessibility

The visible <kbd> elements display "N" and "C" as keyboard keys. The paragraph's accessible label reads "Keyboard shortcuts: N for a new quote, C to copy the quote". The copy and refresh buttons remain available for people who do not use the shortcuts.

Inline content and CSS spacing

The original gap included collapsed whitespace in the HTML, the width of the middle-dot character and the 8-pixel margins on its <span>. After deleting the span, the margin-left value on the "C" key provided one place to control the remaining gap.

Fixed positioning and reserved space

The browser removes a fixed element from the page's normal layout, so other content does not make room for it. Adding bottom padding to body creates that room and reduces the chance of the instruction covering the card on a short screen.

5. Knowledge gaps

How inline gaps are calculated

What the question showed: my follow-up question about how the spacing stayed the same showed that I needed a clearer account of what formed the original gap. Removing one inline element can remove its character width, margins and adjacent whitespace at the same time.

How to check whether two gaps have the same width

What remains uncertain: the fixed margin replaced the separator, but we did not record the width of either version. Browser developer tools can measure each element's position and size. Those figures, backed by before-and-after screenshots, would show whether the gaps are equal or merely look similar.

Keyboard shortcut edge cases

Optional topic: the listener handles Command, Control and Alt combinations, repeated keydown events and editable fields. We did not test how it behaves with different focused elements, alternative keyboard layouts, screen readers or the Shift key.

6. Recommended learning path

The first two steps address questions raised directly by this work. The third would help if the instruction begins to overlap the card on short or enlarged screens.

1. Inline layout and spacing

Why
It explains which parts of the original gap disappeared when the separator was removed.
Understand
How collapsed whitespace, a character's width, CSS margins and the rectangular area assigned to each inline item determine the gap.
Connection
The 23px left margin now replaces the approximate space taken by the middle dot, its margins and surrounding whitespace.
Exercise
Use browser developer tools to measure the positions of "New quote" and the "C" key in both versions, then compare the gap in pixels.

2. Keyboard events and safe shortcuts

Why
Pressing a letter should run a shortcut only when the user is not typing or using another key combination.
Understand
How event.key, the modifier flags, event.repeat and the focused element tell the listener what the user is doing.
Connection
The quote card checks these values before it responds to n or c.
Exercise
Add a temporary text input and confirm that typing "nice" does not change or copy the quote.

3. Optional: fixed instructions on small screens

Why
An instruction fixed to the bottom can cover the card on a short screen or after enlarged text makes the instruction wrap.
Understand
How the browser window's height, device safe areas and the body's bottom padding affect the space available for a fixed instruction.
Connection
The shortcut instruction sits 16 pixels from the bottom, while the body reserves 64 pixels below the card.
Exercise
Use a very short browser window and 200% text zoom. Check whether any part of the instruction covers the card.

7. Key takeaways

  • The keyboard shortcuts call the existing button functions, so the two controls cannot develop separate quote behaviour.
  • The listener ignores editable fields, Command, Control and Alt combinations, and repeated keydown events.
  • position: fixed keeps the instruction at the bottom of the window. Bottom padding stops it from occupying the same space as the card.
  • Deleting the separator removed its character width and margins. A left margin on the "C" key replaced that space.
  • The 23-pixel margin preserves the apparent gap, but only a browser measurement can show whether the old and new widths match exactly.

8. Questions to revisit

  • In pixels, is the new gap the same width as the old one in the browser's computed layout?
  • At 200% text zoom or in a very short browser window, does the instruction cover the card?
  • Should the page ignore shortcuts while the quote is fading, or does the existing isTransitioning check already handle this well enough?
  • Would "Press N" and "Press C" be clearer than the current key-cap labels?
